## 核心组件

系统中的缓存功能主要由以下几个核心组件构成：`CacheStorageController` 负责管理基于浏览器 Cache API 的缓存存储，`AppStorage` 提供基于 IndexedDB 的持久化存储，`memoizeAsyncWithTTL` 实现函数结果的内存缓存，以及 `stream.ts` 中的流式缓存处理机制。

## LRU淘汰策略分析

虽然代码库中没有显式实现传统的LRU（最近最少使用）淘汰算法，但通过 `memoizeAsyncWithTTL` 函数实现了基于时间的缓存淘汰机制。该机制通过设置缓存有效期（TTL）来自动清除过期的缓存条目。

```mermaid
sequenceDiagram
participant Client
participant Cache
participant Function
Client->>Cache : 调用缓存函数
alt 缓存命中
Cache-->>Client : 返回缓存结果
else 缓存未命中
Cache->>Function : 执行原始函数
Function-->>Cache : 返回结果
Cache->>Cache : 设置缓存并启动定时器
Cache-->>Client : 返回结果
end
Note over Cache : 定时器到期后<br/>自动删除缓存条目
```

## 缓存键生成规则

缓存键的生成遵循特定的命名约定和结构。对于文件流缓存，键由文档ID、偏移量和限制大小组成，格式为 `${docId}?offset=${alignedOffset}&limit=${limit}`。对于普通缓存条目，键前会添加斜杠前缀，如 `/${entryName}`。

```mermaid
flowchart TD
Start([生成缓存键]) --> CheckType{缓存类型}
CheckType --> |文件流| GenerateStreamKey["生成流式键:<br/>${id}?offset=${offset}&limit=${limit}"]
CheckType --> |普通缓存| GenerateNormalKey["生成普通键:<br/>/${entryName}"]
GenerateStreamKey --> End([返回键])
GenerateNormalKey --> End
```

## 缓存有效期管理

缓存有效期通过多种机制进行管理。`memoizeAsyncWithTTL` 函数使用 `setTimeout` 在指定时间后自动清除缓存条目。对于流式缓存，系统在响应头中添加 `X-Chunk-Cached-Time` 字段记录缓存时间戳。

```mermaid
sequenceDiagram
participant Cache
participant Timer
Cache->>Cache : 存储缓存条目
Cache->>Timer : 设置定时器(timeoutMs)
Timer->>Cache : 定时器到期
Cache->>Cache : 删除缓存条目
Cache-->>Timer : 清除定时器
Note over Timer : 使用 self.setTimeout<br/>实现延迟删除
```

## 内存缓存与磁盘缓存协同机制

系统实现了内存缓存与磁盘缓存的协同工作机制。`CacheStorageController` 使用浏览器的 Cache API 作为磁盘缓存层，而 `memoizeAsyncWithTTL` 和 `cacheFunctionPolyfill` 则提供了内存缓存层。`MemoryWriter` 类在内存中累积数据，达到条件后写入磁盘缓存。

```mermaid
graph LR

C --> |命中| E[返回数据]
C --> |未命中| D
D --> |命中| F[返回数据并填充内存缓存]
D --> |未命中| G[从源获取数据]
G --> H[写入磁盘缓存]
H --> I[写入内存缓存]
I --> E
```

## 缓存命中与未命中处理流程

缓存命中与未命中的处理流程在 `CacheStorageController` 类中实现。当请求缓存条目时，系统首先检查是否存在对应的响应，如果存在则返回缓存数据，否则返回 undefined 表示缓存未命中。

```mermaid
flowchart TD
A[请求缓存条目] --> B{缓存是否存在?}
B --> |是| C[返回缓存响应]
B --> |否| D[返回 undefined]
C --> E{是否需要解密?}
E --> |是| F[解密数据]
E --> |否| G[直接返回]
F --> H[返回解密后数据]
G --> I[结束]
H --> I
```

## 缓存预加载策略

系统实现了智能的缓存预加载策略，特别是在流媒体处理中。`Stream` 类中的 `preloadChunk` 和 `preloadChunks` 方法会根据当前播放位置预加载相邻的数据块，以提高用户体验。

```mermaid
sequenceDiagram
participant Player
participant Stream
participant Cache
Player->>Stream : 请求数据范围
Stream->>Cache : 检查缓存
alt 缓存命中
Cache-->>Stream : 返回缓存数据
else 缓存未命中
Stream->>Stream : 预加载相邻块
Stream->>Stream : preloadChunk(offset)
Stream->>Cache : 请求数据
Cache-->>Stream : 返回数据
end
Stream-->>Player : 返回数据
Note over Stream : 预加载策略提高<br/>后续请求的命中率
```

## 性能优化考虑

系统在多个层面进行了性能优化。通过 `throttleWith` 函数对存储操作进行节流，减少频繁的磁盘I/O。使用 `cancellablePromise` 管理异步操作，避免资源浪费。同时，通过 `timeoutOperation` 方法为缓存操作设置超时机制，防止长时间阻塞。

```mermaid
flowchart TD
A[性能优化] --> B[操作节流]
A --> C[异步管理]
A --> D[超时控制]
A --> E[内存优化]
B --> F["使用 throttleWith<br/>限制操作频率"]
C --> G["使用 cancellablePromise<br/>管理异步操作"]
D --> H["设置 15秒 超时<br/>防止阻塞"]
E --> I["MemoryWriter 高效管理<br/>内存中的数据写入"]
```
