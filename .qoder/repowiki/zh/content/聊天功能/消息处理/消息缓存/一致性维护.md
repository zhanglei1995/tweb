## 同步策略

系统实现了增量更新和全量同步两种机制，确保本地缓存与服务器数据保持一致。

### 增量更新机制

增量更新通过监听服务器推送的更新消息来实现。当服务器有新的消息或消息状态变更时，会通过更新通道推送更新信息，客户端接收到后立即更新本地缓存。

```mermaid
sequenceDiagram
participant Server as 服务器
participant Client as 客户端
participant Cache as 本地缓存
Server->>Client : 推送更新消息
Client->>Cache : 应用更新
Cache-->>Client : 更新完成
Client-->>Server : 确认接收
```

### 全量同步机制

全量同步在应用启动、网络恢复或手动刷新时触发，通过获取服务器的完整状态来确保本地缓存的完整性。

```mermaid
sequenceDiagram
participant Client as 客户端
participant Server as 服务器
participant Cache as 本地缓存
Client->>Server : 请求差异数据
Server-->>Client : 返回差异结果
Client->>Cache : 应用差异数据
alt 差异数据完整
Cache-->>Client : 同步完成
else 差异数据不完整
Client->>Server : 请求完整状态
Server-->>Client : 返回完整状态
Client->>Cache : 应用完整状态
Cache-->>Client : 同步完成
end
```

## 冲突解决机制

当本地缓存与服务器数据不一致时，系统采用多种策略来解决冲突，确保数据的一致性和完整性。

### 消息ID冲突处理

系统通过消息ID（mid）来识别和处理消息冲突。对于旧版消息ID（小于MESSAGE_ID_OFFSET），系统会使用全局历史存储进行镜像同步。

```mermaid
flowchart TD
Start([开始]) --> CheckLegacy["检查是否为旧版消息ID"]
CheckLegacy --> |是| UseGlobal["使用全局历史存储"]
CheckLegacy --> |否| UsePeer["使用Peer特定存储"]
UseGlobal --> Mirror["镜像到全局存储"]
UsePeer --> Store["存储到Peer存储"]
Mirror --> End([结束])
Store --> End
```

### Pts和Seq冲突处理

系统使用Pts（消息点）和Seq（序列号）来检测和处理更新序列的不一致。当检测到Pts或Seq的不连续时，系统会触发差异同步。

```mermaid
flowchart TD
Start([开始]) --> CheckPts["检查Pts连续性"]
CheckPts --> |不连续| TriggerSync["触发差异同步"]
CheckPts --> |连续| CheckSeq["检查Seq连续性"]
CheckSeq --> |不连续| TriggerSync
CheckSeq --> |连续| NoAction["无需操作"]
TriggerSync --> End([结束])
NoAction --> End
```

```mermaid
flowchart TD
```

## 离线场景处理

系统为离线场景提供了完善的处理方案，确保用户体验的连续性。

### 离线消息缓存

在离线状态下，系统会将用户发送的消息暂存于本地，待网络恢复后自动重发。

```mermaid
flowchart TD
Start([用户发送消息]) --> CheckNetwork["检查网络状态"]
CheckNetwork --> |在线| SendNow["立即发送"]
CheckNetwork --> |离线| StoreLocal["暂存本地"]
SendNow --> End([发送完成])
StoreLocal --> WaitNetwork["等待网络恢复"]
WaitNetwork --> |网络恢复| SendStored["发送暂存消息"]
SendStored --> ClearStore["清除暂存"]
ClearStore --> End
```

### 离线数据访问
